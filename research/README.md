# Research layer

This directory contains independently versioned, reproducible derivatives of the immutable Classical Tamil Corpus. It must never be used to edit, normalise, correct, or supersede canonical transcription.

## Version boundary

- Puṟanāṉūṟu R0 source evidence remains research evidence schema `0.1.0`.
- R1 review and entity-resolution workflow is schema `0.2.0`.
- The R0 assertion IDs, evidence spans, canonical hashes, printed forms, 2,867-assertion inventory, 285 literary-body candidates, 43 pilot entities, and 51 pilot relationships remain the compatibility baseline.
- R1 is reconciled onto the current Corpus 1.1.0 tree without modifying canonical corpus evidence or Tolkāppiyam.

## Directory roles

- `schemas/`: reusable R0 evidence schemas plus R1 workflow schemas.
- `controlled-vocabularies/`: versioned evidence, review, reviewer, and entity-resolution vocabularies.
- `evidence/purananuru/`: authoritative deterministic R0 assertions and reporting CSV.
- `mentions/purananuru/`: unresolved R0 literary-body mention candidates.
- `entities/pilot/`: R0 surface-form entity sample plus append-only R1 entity-resolution decisions.
- `relationships/pilot/`: assertion-supported R0 pilot relationships.
- `reviews/purananuru/`: append-only review events plus deterministic review queues/exports.
- `reports/`: coverage, ambiguity, review, and unresolved-entity reports.

## Primary histories versus generated views

`reviews/purananuru/review-events.ndjson` and `entities/pilot/entity-resolution-decisions.ndjson` are primary histories. They are never regenerated from scratch or silently truncated. Review events are ordered and hash-chained; entity decisions remain assertion-provenanced and auditable.

Review queues, reviewed exports, summaries, ambiguity registers, and unresolved-entity CSV files are deterministic derived views. They may be regenerated byte-for-byte from the primary histories and frozen R0 evidence.

## Review semantics

`machine_checked` is not human verification. `reviewed` requires an explicit review event, and `verified` requires a stronger explicit verification decision. Assistant-assisted review is identified as `assistant_assisted` and does not establish a verified historical identity by itself.

`possible_match` / `POSSIBLY_SAME_AS` remains distinct from verified identity. Exact printed-form equality or lookup-normalised equality never causes an automatic entity merge.

## Regeneration

```bash
python3 scripts/generate_research_layer.py --root .
python3 scripts/generate_research_r1.py --root .
python3 scripts/validate_research_layer.py --root .
python3 scripts/validate_research_r1.py --root .
pytest -q
```

The R0 compatibility wrapper preserves existing append-only review history while delegating all R0 evidence generation to the preserved R0 implementation.

All generated deterministic content excludes execution timestamps. Human/editorial review must append review events rather than mutating assertion history. R1 contains no external-historical or interpretive assertion population; R1.5 is the next permitted research phase after R1 completion.
